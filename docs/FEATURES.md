# OmniMesh — Feature Inventory

Complete inventory of **implemented** product capabilities across Android (`app/`), web dashboard (`web/`), OmniMesh AI backend (`backend/`), and Firebase Cloud Functions (`functions/`). Suitable for product overviews and technical briefs.

**Android APK (no build required):** [app-debug.apk](https://github.com/Adya6714/OmniMesh/releases/download/release-v1.0/app-debug.apk) — release `release-v1.0`.

**Dual dispatch paths:** Google Gemini (existing Firebase/web path) **and** OmniMesh AI backend (LOCAL / CLOUD / HYBRID on AMD GPU + Fireworks Gemma). Both coexist; the dashboard can switch live.

---

## 1. Platform shell

1. **Three operational modes** — Victim / Responder (Field) / Command on one product; same live packet stream, different jobs.
2. **Shared TriagePacket model** — Urgency, injury, GPS, confidence, signal sources, auto/manual flag, hops, origin — lingua franca across mesh, Firestore, and web.
3. **System status strip** — Top edge pulses red / yellow / blue from live RED/YELLOW pressure.
4. **RED cascade alert** — Transient overlay when a new RED packet appears (injury + GPS).
5. **Demo / Real toggle** — Demo merges deterministic sample packets; Real shows live Firestore only. Persisted in `localStorage` (web).
6. **Peer count pill** — Estimated mesh peers (demo preset or activity-derived).
7. **Splash boot** — Short branded mesh animation before the main UI.
8. **Permission bootstrap (Android)** — Requests location, mic, camera, Bluetooth, Nearby Wi‑Fi, notifications; starts mesh + collapse services.

---

## 2. Victim / reporting

9. **Manual emergency report** — Pick RED/YELLOW/GREEN, injury type, optional note, “unable to speak”; attaches location and queues for mesh + Firebase.
10. **Voice SOS** — On-device speech recognition → transcript → RED packet.
11. **Injury photo capture** — Camera shot stored for vision classification / fusion.
12. **START self-triage wizard** — Walk / breathe / pulse / obey commands → START color on the packet.
13. **Web Report Emergency** — One-tap RED AUTO-SOS to Firestore with geolocation.
14. **Web manual triage writers** — CRITICAL / SERIOUS / MINOR (and batch) packet sends.
15. **Last-sent receipt** — Shows urgency, short id, AUTO vs MANUAL, time.
16. **Nearby Triage jump** — If RED packets exist, switch straight into Responder/Field.

---

## 3. Auto-SOS & on-device sensing

17. **Collapse detector service** — Foreground 50 Hz accel/gyro sampling with sticky restart.
18. **LSTM motion classifier** — On-device TFLite (NNAPI): collapse_unconscious, collapse_moving, fall_phone, car_crash, running, normal → can fire auto-SOS.
19. **Impact + stillness rule** — Hard impact then stillness → auto-SOS without waiting on the LSTM.
20. **Auto-SOS packet** — RED, `isAutoGenerated`, fused location + confidence + signal sources; cooldown.
21. **Acoustic SOS beacon** — Loud Morse-style tone so SAR can hear a buried phone; silenceable in UI.
22. **Post-SOS companion kickoff** — After auto-SOS, starts the Gemini disaster companion for that packet.
23. **Structural danger zone** — High collapse confidence can place a ~25 m danger circle for responders.
24. **Boot auto-restart** — After reboot, restarts mesh relay and sync jobs.

## 4. Disaster companion

25. **Gemini companion chat** — Calm first-aid guidance, condition assessment, clinical fields written onto the packet.
26. **Urgency escalation** — Companion can raise severity to RED if the victim worsens.
27. **Periodic check-ins** — Keeps pinging the victim after auto-SOS.
28. **Companion STT/TTS** — Hands-free speech input and spoken replies.
29. **Disaster context** — Earthquake / flood / cyclone / industrial colors companion prompts and status.

## 5. Buddy / FCM alerts

30. **Buddy groups** — Create / join / leave via join code in Firestore.
31. **Device + FCM registration** — Tokens stored under registered devices for group alerts.
32. **Buddy auto-alert on auto-SOS** — Queues FCM with victim lat/lon to other group members.
33. **`sendBuddyAlerts` Cloud Function** — Drains `pending_fcm_alerts` and sends high-priority push.

---

## 6. Mesh networking

34. **Nearby Connections mesh** — P2P advertise + discover; auto-accept; no manual pairing.
35. **Priority packet relay** — Broadcasts queue RED → YELLOW → GREEN → BLACK; RED flushes immediately on new peer connect.
36. **Store-and-forward + dedupe** — Save locally, relay to other peers, ignore known IDs (loop prevention).
37. **Hop / origin metadata** — Packets carry hop count and originating device id across the mesh.
38. **Mesh foreground service** — Keeps advertising/discovery/relay alive with an ongoing notification.
39. **Walkie-talkie PTT** — Push-to-talk PCM audio carried over the same Nearby mesh.

---

## 7. Location & maps

40. **Fused GPS on packets** — Continuous location updates feed SOS coordinates.
41. **Indoor location manager** — Best of GPS, RSSI peer triangulation, last-known; optional floor.
42. **Barometric floor estimator** — Pressure → floor; calibrated from good GPS altitude.
43. **Responder Google Map (Android)** — Night style, urgency pins, sonar sweeps, danger zones, sector circles.
44. **Field map (web)** — Google Maps if API key present, else Leaflet; pins, heat layer, open-in-Maps, fit bounds.
45. **Field breadcrumbs** — Trail when responder moves ≥ ~3 m in enter-field mode.
46. **Sector claim / clear** — Claim a labeled search sector; mark cleared so teams don’t overlap.

50. **Data quality badge** — Trust score from signal sources + confidence + confirmed/disputed flags.

54. **Structural danger overlays** — Map zones from motion/structural confidence.

65. **Incident timeline** — RED receipts, auto-SOS, confirms, Gemini runs, structural warnings.

69. **`onRedPacketTriggerDispatch` Cloud Function** — RED Firestore write → Gemini → `dispatch_analysis/latest`.

## 10. OmniMesh AI backend (AMD / FastAPI)

70. **Hybrid routing orchestrator** — Per-packet LOCAL / CLOUD / HYBRID with a human-readable `reasoning_trace`.
71. **Uncertainty-aware triage** — Confidence + `uncertainty`; flags `needs_human_review` when low confidence / unknown.
72. **LOCAL path** — Gemma on AMD GPU via vLLM-ROCm, else START heuristic (system never goes dark).
73. **CLOUD path** — Fireworks Gemma (AMD-hosted) for best-quality reasoning.
74. **HYBRID path** — Instant local answer, then cloud reconcile on critical cases.
75. **Translation agent** — Non-English reports → English via Gemma; offline queues reconcile.
76. **Vision damage agent** — Photo → structural damage level / hazards / entry_safe.
77. **Missing-person matching** — Semantic rank of candidates with LLM explanation; offline token-cosine fallback.
78. **A\* route planner** — Occupancy-grid pathfinding; zero LLM tokens.
79. **Resource allocation** — Severity-first greedy assignment of units to victims.
80. **Live GPU proof** — `GET /v1/gpu-status` confirms Gemma is loaded on the AMD GPU. Static evidence: [`backend/rocm-smi-proof.png`](../backend/rocm-smi-proof.png) (`rocm-smi` + `docker ps`).
81. **Infra + health** — Which cloud/local inference paths are configured and live.
82. **Connectivity API** — Force uplink down for LOCAL-only demos (`POST /v1/connectivity/on|off`).

---

## 11. Firebase & sync

83. **Anonymous Auth** — Silent sign-in so Firestore rules can require `auth != null`.
84. **Room DB (Android)** — Local packets, timeline events, breadcrumbs, sector claims, danger zones.
85. **Packet repository** — Priority queue, dedupe, clinical updates, cleanup of old synced rows.
86. **Firestore `packets` sync** — Batch upload of unsynced packets; real-time listeners on web/Android.
87. **WorkManager sync** — Periodic (network-required) + immediate one-shot sync with backoff.
88. **Immediate sync on write** — Saving/updating a packet also kicks in-process Firebase sync.

89. **Deterministic demo dataset** — Stable SF-anchored packets + fixed peer count for recordings.

## 13. Vision & ML

95. **Vision classifier (Android Gemini)** — Injury/scene photo → RED/YELLOW/GREEN/BLACK/STRUCTURAL with probabilities.
96. **Motion + vision fusion** — Combines sensors into injury text, `M`/`V` sources, fused confidence.
97. **Firebase ML model update** — Background Wi‑Fi download of updated `.tflite` motion models.
